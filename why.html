Why SEED Emulator

传统网络仿真器解决不了全部网络安全需求

许多工具更擅长网络层或设备级仿真，但网络安全实验往往需要完整的互联网基础设施和应用层生态。SEED Emulator 的目标，就是把这些复杂组件放进一个可编程、可复现、可运行的实验环境。

🧱

真实互联网不止拓扑

网络安全问题往往横跨自治系统、路由、DNS、Web 服务和应用软件。只看到链路和设备，很难解释攻击从哪里进入、怎样传播、为什么影响业务。

🧩

真实环境不适合试错

BGP 劫持、蠕虫传播、Botnet 控制链路、智能合约攻击等实验都需要可控边界。SEED 把高风险动作放进隔离的“小型互联网”，便于观察和复盘。

🛡️

手工搭建难以复现

课程和科研都需要可重复的环境。SEED 用 Python SDK 描述实验，再编译成 Docker 或 Kubernetes 运行文件，让拓扑、服务和攻击流程都能版本化。

From Network To Internet

SEED 关注的是“可运行的互联网实验场”

SEED Emulator 以 Python SDK 为核心，提供自治系统、网络、主机、路由器、BGP 路由器、互联网交换中心等互联网基础构件，也提供 DNS、Web、区块链、Botnet、Darknet 等服务构件。用户用代码组合实验场景，生成一个可以启动、交互、观察的小型互联网。

01 像互联网一样组织

用 AS、IXP、BGP peer、DNS 层级和服务节点描述真实互联网结构。

02 像系统一样运行

编译后生成容器文件，由 Docker 或 Kubernetes 承载，节点中可以运行真实软件。

03 像实验一样复现

同一份 Python 描述可以反复生成，适合教学实验、科研验证和演示展示。

Why It Matters

它补上的不是一个功能，而是一整条实验链路

传统设备或拓扑仿真

重点在网络结构

适合观察链路、设备和协议行为，但要同时组织 DNS、Web、区块链、恶意软件传播等上层生态时，往往需要大量手工拼接。

SEED Emulator

重点在互联网生态

把 AS、IXP、BGP、DNS 与应用服务统一在一个实验描述里，让“网络如何支撑攻击或防御”变成可以运行的实验。

真实互联网实验

风险和成本都太高

真实网络不可随意破坏，也难以复现边界条件。SEED 提供隔离环境，让学生和研究者可以安全地观察攻击链路与系统响应。

Typical Labs

适合承载更接近真实互联网的安全实验

平台可以承载多个贴近真实互联网的实验方向，包括 BGP、DNS、区块链、Morris Worm、Botnet 和 Darknet 等。

🛰️

BGP 探索与劫持

构造多个自治系统和互联网交换中心，观察路由传播、前缀劫持和跨 AS 影响。

🌍

DNS 基础设施

搭建 root、TLD、权威服务器等层级，理解解析链路以及 DNS 相关攻击面。

⛓️

区块链与智能合约

把以太坊等真实系统部署进仿真互联网，用可控网络环境观察合约与节点行为。

🧬

蠕虫、Botnet 与暗网

在隔离环境中复现传播、控制和匿名通信路径，适合讲解攻击链与防御策略。
